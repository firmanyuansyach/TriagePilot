- **Rovo agent** (`triagepilot-agent`): prompt in `prompts/prompt.md`,
  conversation starters, three actions (`get-issue-context`,
  `find-similar-issues`, `propose-triage`). The prompt forbids the agent
  from changing Jira directly and forbids Forge LLM API use.
- **Triage engine** (`src/triage.js`): `scorePriority` (severity keywords
  + labels + high-impact components + Bug type; explicitly set Jira
  priority is kept as a floor), `buildDuplicateJql` (distinctive summary
  terms -> JQL), `detectDuplicates` (Jaccard >= 0.5 on summary tokens),
  `missingInfoChecklist` (assignee / short description / no repro steps /
  no priority / no component-or-label), `suggestArea` (component -> team
  map), `adfToText` (ADF description -> plain text). Every rule is
  explainable in one line; every proposal carries its reasons.
- **Backend** (`src/index.js`): reads issue + linked Confluence pages
  (remote links + first 500 chars of page body, read-only, per-page
  failure degrades gracefully), JQL similar-issue search, proposal
  assembly. **The only write path is `applyApproval`, which throws
  unless `approved === true`** and then only sets the approved priority,
  adds the `triagepilot-reviewed` label and posts one audit comment.
  `dismissProposal` writes nothing.
- **Panel** (`src/frontend/index.jsx`): shows proposal + reasons +
  duplicate warnings + missing-info checklist + linked pages, with
  Approve / Dismiss buttons calling the resolver via `invoke`.

## Quality audit fixes (26 Nov ~15:40 WIB, deep audit -> v3.0.0)

All 12 audit fixes implemented in this directory only; deployed to
development only; nothing written to Jira/Confluence, nothing submitted.

1. **Owner-area fallback (highest impact).** `suggestArea` now falls back
   to keyword matching against summary + description when no component
   or label matches, via new `suggestAreaWithSource` returning
   `{ area, source }` (source: component / label / keywords / none).
   The proposal carries `suggestedArea` + `suggestedAreaSource`; the
   panel shows e.g. "Platform / Auth (from summary keywords)". Test:
   summary "App crashes on login with SSO", no components/labels ->
   "Platform / Auth".
2. **Non-standard priority floor.** `scorePriority` keeps a current Jira
   priority that is NOT in `PRIORITY_LEVELS` (e.g. the demo site's custom
   "Critical") as the proposal, with a reason saying so. Test with
   priority "Critical".
3. **Panel visuals.** UI Kit 2 `Heading` (proposal title), `Lozenge`
   (proposed priority; danger/warning/information/neutral by level),
   `SectionMessage` warning for duplicates. Imports verified in
   @forge/react 12.6.0 `.d.ts` before use. All existing content kept.
4. **Confluence excerpts in the panel.** Each linked page renders its
   excerpt under its title, truncated to ~200 chars.
5. **Confluence page-id extraction.** `fetchLinkedConfluencePages` also
   matches `viewpage.action?pageId=<id>` in addition to `/pages/<id>/`.
   The `/atlassian.net/wiki/` filter is unchanged.
6. **Unused scopes removed from manifest.yml:** `read:jira-user` and
   `search:confluence` (plus the false "CQL search" comment). Kept:
   `read:jira-work`, `write:jira-work`, `read:confluence-content.all`.
   Verified unused by grep over `src/` first. `forge lint` clean
   (0 errors, 0 warnings) apart from the known PermissionLinter
   "Unknown product" quirk; scope removal triggers a MAJOR_VERSION_RULE
   approval, acknowledged at deploy with `--approve MAJOR_VERSION_RULE`.
7. **Already-reviewed state.** The proposal carries `alreadyReviewed`
   (labels include `triagepilot-reviewed`) and `currentPriority`. When
   true, the panel shows "Already reviewed — priority X was applied"
   instead of the Approve/Dismiss buttons.
8. **Partial-write safety.** The audit-comment POST in `applyApproval`
   is wrapped in try/catch (including an `res.ok` check): a failed
   comment is logged, the priority change still reports success, and
   no "Apply failed" invites a retry that would duplicate the comment.
9. **Server-side recompute in `applyApproval`.** The proposal is
   recomputed from the live issue and ITS priority is used; the
   frontend no longer sends a priority value. Standard priorities are
   written as before; a non-standard current priority (fix 2) is left
   unchanged rather than written (it cannot pass standard validation),
   and anything else still throws. `approved === true` still required.
10. **Duplicate recall.** (a) `extractSearchTerms` and the duplicate
    tokeniser now also keep 3-letter all-uppercase tokens (SSO, API).
    (b) New `findRelatedIssues` returns `{ duplicates, possiblyRelated }`;
    0.3–0.5 similarity goes to `possiblyRelated` (cap 3, sorted);
    >= 0.5 stays in `duplicateWarnings`. `detectDuplicates` is kept as
    a wrapper returning only the duplicate tier. The panel renders
    "Possibly related" as a separate section.
11. **Score display.** Panel shows "severity score 45" — no "/100".
12. **Docs hygiene.** This file: "12 cases" -> true test count (25),
    header status corrected, "panel and agent can never disagree"
    (src/index.js comment) softened to "share the same deterministic
    proposal; the agent may add context in prose".
